You are a senior React Native engineer responsible for building a polished, production-quality React Native application for a technical hiring assignment.

IMPORTANT:
Build this application incrementally in clearly separated phases.

Do NOT try to implement everything at once.

After completing each phase:
1. Verify that the application still runs.
2. Check that existing functionality has not been broken.
3. Fix any issues before continuing.
4. Keep the code clean and maintainable.
5. Do not rewrite working functionality unnecessarily.
6. Do not move to the next phase until the current phase is stable.

The goal is NOT to build a huge application.

The goal is to build a smaller, polished, smooth and reliable video-first mobile experience that demonstrates strong React Native engineering.

============================================================
ASSIGNMENT OVERVIEW
============================================================

Build a video-first React Native mobile application with:

- Home video feed
- 15–20 mock videos
- Horizontal categories
- Shorts preview section
- Full-screen vertical Shorts viewer
- Working video playback
- Correct video lifecycle management
- Shared-element-style Home → Watch transition
- Gesture-driven Watch → Mini Player interaction

- Smooth scrolling
- Smooth animations
- Clean TypeScript architecture
- Good performance
- Loading and error states

The most important evaluation areas are:

1. Smoothness
2. Gestures and animations
3. Video lifecycle
4. Architecture
5. UI polish

Performance, reliability and interaction quality are more important than decorative UI.

PHASE 5 — VIDEO LIFECYCLE + SHORTS PERFORMANCE
============================================================

Goal:

Make Shorts reliable under rapid interaction.

This is a critical phase.

Implement a strict active-video strategy.

RULE:

Only the currently visible Short should actively play.

When the active index changes:

Previous:
    pause

Current:
    play

Next:
    optionally prepare/preload

Far-away Shorts:
    remain inactive

Do NOT preload every Short.

Prevent:

- Multiple videos playing simultaneously
- Overlapping audio
- Frozen players
- Stale player references
- Playback leaks
- Unnecessary mounted players
- Excessive memory/resource consumption

Rapid swipe test:

Short 1
↓
Short 2
↓
Short 3
↓
Short 4
↓
Short 5

After the final swipe:

Only Short 5 should be actively playing.

Also test:

Enter Shorts
→ swipe rapidly
→ exit
→ re-enter
→ swipe again

The app must remain stable.

Use Reanimated/Gesture Handler appropriately.

Avoid unnecessary JS-thread work during gestures.

At the end of Phase 5:

- Only the visible Short plays.
- Off-screen videos pause.
- Rapid swiping does not create overlapping audio.
- Re-entering Shorts works correctly.
- Video resources are cleaned up.

PHASE 11 — GLOBAL PERFORMANCE OPTIMIZATION
============================================================

Goal:

Perform a complete performance pass.

Review the entire application.

HOME FEED
---------

Ensure:

- FlashList/FlatList

SHORTS
------

Ensure:

- Only active video plays
- Off-screen videos pause
- Limited preloading
- Proper cleanup
- No overlapping audio
- No unnecessary mounted players

ANIMATIONS
----------

Use Reanimated for high-frequency animations.

Avoid driving continuous gesture animations through normal React state.

PLAYER
------

Make sure inactive players are cleaned up.

IMAGES
------

Use efficient image loading/caching where supported.

Avoid unnecessarily loading huge images.

RENDERING
---------

Look for:

- Unnecessary Context updates
- Excessive state
- Large component trees
- Inline objects passed to memoized components
- Inline callbacks where avoidable
- Expensive calculations during scrolling

Do not blindly add useMemo/useCallback everywhere.

Use them where they actually improve stability/performance.
